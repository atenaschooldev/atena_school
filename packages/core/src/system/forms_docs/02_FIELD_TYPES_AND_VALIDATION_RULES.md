# 🎛️ 02. Типы полей и правила валидации

Спецификация всех поддерживаемых типов полей, вариантов их конфигурации и механизмов валидации.

---

## 1. Поддерживаемые типы элементов (`FormFieldType`)

| Тип (`field_type`) | Виджет в UI | Описание | Поддерживаемые свойства |
|---|---|---|---|
| `text` | `<input type="text">` | Однострочный текст | `placeholder`, `validation_pattern`, `help_text` |
| `select` | `<select>` | Выпадающий список | `options: [{ label, value }]`, `placeholder` |
| `textarea` | `<textarea>` | Многострочный текстовый блок | `placeholder`, `help_text` |
| `checkbox` | `<input type="checkbox">` | Чекбокс / Согласие | `placeholder` (текст согласия), `help_text` |
| `number` | `<input type="number">` | Числовой ввод | `placeholder`, `help_text` |
| `date` | `<input type="date">` | Выбор календарной даты | `placeholder`, `help_text` |

---

## 2. Формат опций для выпадающих списков (`select`)

В визуальном конструкторе опции задаются списком строк вида `Название:значение`:
```text
Principiante assoluto:A1
Elementare:A2
Intermedio:B1
Avanzato:B2
```

При сохранении преобразуется в типизированный JSON-массив:
```json
[
  { "label": "Principiante assoluto", "value": "A1" },
  { "label": "Elementare", "value": "A2" },
  { "label": "Intermedio", "value": "B1" },
  { "label": "Avanzato", "value": "B2" }
]
```

---

## 3. Таргетинг полей (`FormFieldTarget`)

Каждое поле привязывается к логическому блоку анкеты:
* **`purchaser`**: Данные плательщика/родителя (например, *«Откуда вы о нас узнали?»*, *«Требуется ли электронная фактура?»*).
* **`student`**: Данные студента/ребёнка (например, *«Текущий уровень языка»*, *«Школа / Класс»*, *«Смена обучения»*).
* **`booking`**: Общие параметры заявки (например, *«Особые пожелания к расписанию»*, *«Наличие аллергий»*).

---

## 4. Динамическая валидация

1. **Обязательность (`is_required`):**
   - Если `is_required: true`, клиентская форма и серверные сервисы отклоняют сабмит с пустым значением.
2. **Активность (`is_enabled`):**
   - Если `is_enabled: false`, поле скрыто от пользователя на лендинге и игнорируется при валидации.
3. **Регулярные выражения (`validation_pattern`):**
   - Опциональная проверка по Regex (например, для проверки почтовых индексов CAP или форматов номеров).
