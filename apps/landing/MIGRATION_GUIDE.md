# Руководство по передаче проекта заказчику (Handoff) и миграции в Production

Этот документ описывает пошаговый процесс передачи проекта (Next.js + Supabase + Stripe) на аккаунты конечного заказчика, а также процесс перевода платежной системы из тестового режима (Test Mode) в боевой (Live Mode).

---

## Шаг 1. Настройка нового Supabase (База данных и Бэкенд)

Поскольку все данные хранятся в Supabase, вам потребуется создать новый проект на аккаунте заказчика.

1. **Создание аккаунта:** Заказчик должен зарегистрироваться на [Supabase](https://supabase.com/) и создать новую организацию и проект (Project). Вы можете попросить его добавить ваш email в качестве администратора (Team Member) в его организации на период настройки.
2. **Перенос структуры базы данных:** 
   * В вашем существующем проекте (Supabase Dashboard) зайдите в **SQL Editor**.
   * Если у вас есть скрипты создания таблиц (Migrations), скопируйте их.
   * На новом Supabase выполните SQL-запросы для создания таблиц (`bookings`, `shop_items`, `users` и т.д.) и настроек RLS (Row Level Security), которые мы делали ранее.
3. **Обновление ключей Supabase в коде:**
   * Откройте меню **Project Settings -> API** в новом проекте заказчика.
   * Скопируйте **Project URL** и **anon/public key**.
   * Замените старые значения в файле `.env.local` или в панели хостинга (например, Vercel).
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://[ID_НОВОГО_ПРОЕКТА].supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbG...
   ```
4. **Настройка авторизации (Auth) на новом Supabase:**
   * Зайдите в раздел **Authentication -> URL Configuration** и укажите там финальный домен сайта (например, `https://atenaschool.com`).
   * Если вы используете вход через Google/Apple, не забудьте настроить там новые Client ID в **Authentication -> Providers**.

## Шаг 2. Настройка Stripe (Платежи) на аккаунте заказчика

Заказчику необходимо зарегистрировать бизнес-аккаунт Stripe.

1. **Регистрация Stripe:** Заказчик должен пройти регистрацию на [Stripe.com](https://stripe.com/), заполнить данные о компании (KYC) и привязать реальный счет в банке. Аналогично Supabase, он может пригласить вас как разработчика (Developer) в свой Team (настройки `Team`).
2. **Получение API Ключей:**
   Перейдите в раздел **Developers -> API keys**. Для начала нужны тестовые ключи (Test Mode) нового аккаунта, чтобы убедиться, что связка работает, а затем боевые ключи.
   * Замените в вашем коде/переменных хостинга ключи Stripe на новые:
   ```env
   NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_... # Затем поменяете на pk_live_...
   STRIPE_SECRET_KEY=sk_test_... # Затем поменяете на sk_live_...
   ```

## Шаг 3. Деплой Supabase Edge Functions (Вебхук и оформление сессий)

В проекте используются функции (Edge Functions). Их нужно выгрузить в новый проект Supabase:

1. **Авторизация в Supabase CLI:** Откройте терминал и выполните вход в аккаунт, где лежит новый проект.
   ```bash
   supabase login
   ```
2. **Привязка проекта:** Свяжите локальную папку с новым проектом.
   ```bash
   supabase link --project-ref [ID_НОВОГО_ПРОЕКТА]
   ```
3. **Публикация функций:** Загрузите функции создания сессии и вебхука на новый сервер:
   ```bash
   supabase functions deploy create-checkout-session
   supabase functions deploy stripe-webhook
   ```
4. **Установка секретов в Edge Functions:** Серверные функции Supabase должны знать `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET` от аккаунта заказчика.
   ```bash
   supabase secrets set STRIPE_SECRET_KEY=sk_test_...
   supabase secrets set STRIPE_WEBHOOK_SECRET=whsec_...
   ```

*(Секрет вебхука `whsec_...` мы получим на следующем шаге)*

## Шаг 4. Настройка связи Stripe и Supabase (Webhooks)

Чтобы при успешной оплате курс добавлялся ученику, Stripe должен отправлять сигнал в Supabase (Webhook).

1. В новом Stripe зайдите в **Developers -> Webhooks**.
2. Нажмите **Add an endpoint**.
3. В поле **Endpoint URL** вставьте адрес вашей функции на новом Supabase проекта:
   `https://[ID_НОВОГО_ПРОЕКТА].supabase.co/functions/v1/stripe-webhook`
4. В разделе **Select events to listen to** выберите событие: `checkout.session.completed`.
5. Сохраните. Stripe выдаст вам "Signing secret" (начинается с `whsec_...`).
6. Сохраните этот ключ в Supabase как секрет для вашей функции (см. шаг 3.4).

## Шаг 5. Миграция с Тестовой (Test Mode) оплаты на Настоящую (Live Mode)

Когда сайт полностью готов, и заказчик готов принимать реальные деньги, вам предстоит нажать "главный рубильник".

1. **Активация Stripe:**
   В панели Stripe выключите переключатель **Test mode** (в правом верхнем углу). Теперь интерфейс показывает настоящие данные.
2. **Смена ключей в коде/хостинге сайта:**
   Зайдите в `Developers -> API Keys` уже в "Боевом" режиме.
   Обновите переменные в `Vercel` (или там, где у вас хостится Next.js):
   * `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` ➔ `pk_live_...`
3. **Смена приватных ключей в базе данных (Supabase):**
   * Зайдите в Vercel/хостинг и обновите `STRIPE_SECRET_KEY` ➔ `sk_live_...`
   * Обновите ключ для самих Edge Functions через терминал:
     ```bash
     supabase secrets set STRIPE_SECRET_KEY=sk_live_...
     ```
4. **Смена ключа Вебхука (Очень важно!):**
   * В "Боевом" режиме Stripe вам нужно заново создать Webhook (см. **Шаг 4**), так как старый работал только для тест-мода!
   * Endpoint URL остается тем же: `https://[ID_НОВОГО_ПРОЕКТА].supabase.co/functions/v1/stripe-webhook`
   * Подписываемся на событие `checkout.session.completed`.
   * Берем новый, боевой секрет вебхука (`whsec_live_...` или обычный `whsec_...`) и устанавливаем в базу данных:
     ```bash
     supabase secrets set STRIPE_WEBHOOK_SECRET=Новый_Боевой_Секрет_Вебхука
     ```
     
### Проверка боевого режима:
Лучший способ проверить — зайти на опубликованный `https://atenaschool.com`, добавить себе tempo-курс (или изменить его цену на €1), после чего произвести настоящую оплату своей банковской картой. 
Если статус брони в Supabase изменился с `in_cart` на `paid` — поздравляю, проект успешно передан и готов принимать заявки и деньги!

## Шаг 6. Миграция домена, SEO и веб-аналитики (GTM + GA4)

Этот шаг описывает, как перевести сайт с тестового хостинга на основной домен, а также подключить реальные счетчики аналитики.

### 1. Перевод домена на боевой (Vercel)
* **Временный хостинг:** `https://atena-school-landing-three.vercel.app/`
* **Боевой домен:** `https://atenaschool.com`
* **Настройка на Vercel:**
  1. В панели Vercel добавьте ваш собственный домен `atenaschool.com` в настройках проекта (**Settings -> Domains**).
  2. Перейдите в раздел **Settings -> Environment Variables** и отредактируйте/добавьте переменную `NEXT_PUBLIC_SITE_URL` со значением `https://atenaschool.com`.
  3. Сделайте повторный деплой (Redeploy) с очисткой кэша сборки, чтобы изменения вшились во все метаданные, канонические ссылки (`canonical`), XML-карту сайта (`sitemap.xml`) и схемы поисковой оптимизации JSON-LD.
  * *Примечание:* В коде прописан авто-фоллбек. Если вы забудете настроить эту переменную, сайт по умолчанию подставит `https://atenaschool.com` в продакшен-режиме.

### 2. Подключение реальных кодов аналитики (GA4 + GTM + Clarity)
Во избежание отправки ложных данных в кабинеты во время тестов, в коде используется строгая фильтрация. При замене ключей на боевые выполните следующие шаги:
* Зарегистрируйте боевой поток данных в Google Analytics 4, контейнер в Google Tag Manager и проект в Microsoft Clarity.
* Добавьте их ID в переменные окружения Vercel (**Settings -> Environment Variables**):
  - `NEXT_PUBLIC_GA_ID` ➔ `G-XXXXXXXXXX` (код вашего потока GA4)
  - `NEXT_PUBLIC_GTM_ID` ➔ `GTM-XXXXXXX` (код контейнера GTM)
  - `NEXT_PUBLIC_CLARITY_ID` ➔ `clXXXXXX` (ID проекта Microsoft Clarity)
* **Важно:** Перезапустите деплой на Vercel, так как переменные с префиксом `NEXT_PUBLIC_` вшиваются в клиентский бандл JavaScript на этапе компиляции (Build-time).
* **Настройка в GTM:** Не забудьте нажать кнопку **Submit -> Publish** внутри личного кабинета Google Tag Manager, чтобы опубликовать контейнер. Без этого скрипты GTM будут возвращать ошибку 404.

### 3. Отладка и Google Consent Mode v2
Наш загрузчик аналитики работает в режиме отложенной загрузки и поддерживает GDPR Consent Mode v2:
* Скрипты загружаются только при первом взаимодействии пользователя (клик, скролл, нажатие клавиши) или через 4 секунды простоя. Это сделано для сохранения 100/100 баллов скорости в Google PageSpeed.
* По умолчанию все куки заблокированы (`denied`). Если пользователь отклоняет куки, GA4 и Microsoft Clarity работают в анонимном режиме (cookieless pings / анонимный режим записи сессий), не оставляя следов в браузере, но отправляя базовые визиты. Если соглашается — куки активируются (`granted`).
* **Как отлаживать в Preview Mode:** 
  1. При подключении через Google Tag Assistant в URL автоматически добавляются параметры `gtm_debug` или `gtm_preview`.
  2. Наш код определяет эти параметры и мгновенно отключает любые задержки, чтобы отладчик подключился сразу.
  3. **Важно:** При тестировании отключайте в браузере блокировщики рекламы/трекеров (uBlock, Privacy Badger, Decentraleyes), так как они полностью блокируют отправку запросов на сервера Google и Microsoft на сетевом уровне.
