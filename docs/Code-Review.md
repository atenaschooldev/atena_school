# Code-Review.md

# Code Review Guide

Purpose: provide a consistent review process for human reviewers and AI agents.

---

# Review Philosophy

The goal of review is to improve the codebase.

Review the code, not the author.

Prefer objective feedback over personal preference.

---

# Review Order

Review in this order:

1. Correctness
2. Architecture
3. Security
4. Performance
5. Maintainability
6. Readability
7. Style

Do not start with formatting.

---

# Architecture

Verify:

- Feature First respected
- Correct layer boundaries
- No business logic in UI
- Repository pattern respected
- DataSource not accessed directly
- Public APIs used correctly

Reject changes that violate architecture.

---

# Feature Review

Ask:

- Does this belong to this feature?
- Should it extend an existing feature?
- Is anything duplicated?
- Does the feature remain cohesive?

---

# UI Review

Pages:

- compose screens only

Components:

- one responsibility
- reusable
- readable

Forms:

- React Hook Form
- Zod validation

Reject API calls inside UI.

---

# State Review

Server state:

- TanStack Query

Shared client state:

- Zustand

Local state:

- useState

Reject duplicated state.

---

# API Review

Verify:

UI
↓
Query Hook
↓
Repository
↓
DataSource

Reject shortcuts.

---

# Performance

Check:

- unnecessary rerenders
- repeated API calls
- large lists virtualized
- lazy loading considered
- dead code removed

Avoid premature optimization.

---

# Naming

Verify Naming.md.

Names should explain intent.

Reject unclear names.

---

# Imports

Check:

- aliases used
- no deep relative imports
- no internal feature imports
- public API respected

---

# Dependencies

Do not introduce new libraries unless justified.

Prefer existing project stack.

---

# Security

Review:

- authentication
- authorization
- sensitive data
- environment variables
- client/server boundaries

Never expose secrets.

---

# Documentation

If architecture changes:

- update documentation
- update ADR if required

---

# Pull Request Checklist

Before approval verify:

[ ] Builds successfully
[ ] TypeScript passes
[ ] Lint passes
[ ] Tests pass
[ ] Architecture respected
[ ] Naming consistent
[ ] No duplicated logic
[ ] No unnecessary dependencies
[ ] Documentation updated

---

# AI Review Checklist

If code was generated by AI verify:

[ ] Existing patterns reused
[ ] No invented architecture
[ ] No business logic in UI
[ ] Correct feature structure
[ ] Repository pattern respected
[ ] Import boundaries respected
[ ] No forbidden practices from Anti-Patterns.md

Reject AI code that violates project standards.

---

# Approval Criteria

Approve only if the change:

- solves the requested problem
- improves or preserves architecture
- does not introduce technical debt
- remains understandable
- follows the Engineering Specification
