## 1. Архитектура и структура проекта

### ✅ Сильные стороны:
1. **Feature-Driven структура:** Код организован по доменным модулям (`features/checkout`, `features/courses`, `features/reviews`, `features/contact`, `features/test-inglese`). Это предотвращает спагетти-код в компонентах.
2. **Переиспользование монорепозитория:** Лендинг активно использует общие пакеты `@atena/validators`, `@atena/utils` (включая единственный источник правды по датам — `calculateLessonDates`) и `@atena/api-types`.
3. **BFF (Backend-For-Frontend) паттерн:** Серверные функции изолированы в `lib/server/services/`, не протекают в клиентский бандл.
4. **Модульные доменные сервисы:** Бизнес-логика бэкенда лендинга декомпозирована по доменам (`course.service.ts`, `student.service.ts`, `reservation.service.ts`, `stripe.service.ts`, `contact.service.ts`, `fee-service.ts`, `email-service.ts`), повторяя архитектуру NestJS.

### ⚠️ Зоны роста:
1. **Синхронизация с будущим NestJS:** Когда NestJS бэкенд будет задеплоен на постоянный хостинг, Route Handlers смогут переключиться на вызовы NestJS REST API через `@atena/api-client`.

## 2. Оптимизация и Core Web Vitals (CWV)

### ✅ Сильные стороны:
1. **Шрифты без layout shift:** Используется `next/font/google` (`Nunito` с `display: 'swap'` и CSS-переменной), что минимизирует FOUT/CLS.
2. **Предзагрузка и Preconnect:** В `RootLayout` настроены `<link rel="preconnect">` для `googletagmanager`, `google-analytics` и `clarity.ms`.
3. **Оптимизация ассетов:** Локальные промо-картинки переведены в `.webp`, внешние домены зарегистрированы в `remotePatterns` (`cdn.sanity.io`, `*.supabase.co`).
4. **Ленивые/клиентские островки:** Статичные элементы рендерятся на сервере, клиентские интерактивы (`CourseDetailClient`, `EnglishTestQuiz`) вынесены в Client Components.

### ⚠️ Зоны роста:
1. **`export const dynamic = 'force-dynamic'` на `/corsi`:** Страница каталога курсов генерируется заново на каждый входящий HTTP-запрос, делая запросы в базу данных.  
   *Рекомендация:* Использовать ISR с ревалидацией (например, `revalidate = 60` или On-Demand Revalidation по тегу через Server Actions/вебхук админки). Это снизит TTFB до единиц миллисекунд и разгрузит Supabase.
2. **Тяжелые анимации и бандл:** `HeroSection` содержит много логики анимаций и разметки. Важно следить, чтобы анимации GSAP запускались после первого рендера без блокировки FID/INP.

## 3. Качество кода и типизация

### ✅ Сильные стороны:
1. **Строгая Zod-валидация:** Валидация всех входящих данных на входе в API ручки (`createReservationSchema.safeParse`, `contactFormSchema.safeParse`).
2. **Конфигурация окружения `config/env.ts`:** Все `process.env` валидируются при старте приложения с помощью Zod, предотвращая падения в рантайме из-за отсутствующих ключей.
3. **Поддержка итальянских фискальных требований:** Учтены `Codice Fiscale`, `SDI`, `PEC`, дифференциация покупателя (родитель) и фактического ученика (ребенок).

### 🎯 Статус улучшений:
1. **Строгая типизация (Выполнено ✅):** Все остаточные `as any` касты полностью устранены по всему `apps/landing/src` (включая `layout.tsx`, `sitemap.ts`, `[id]/page.tsx`, `GoogleAnalytics`, `useBooking`, `course.service.ts`). Монорепозиторий и лендинг компилируются со 100% строгой типизацией.
2. **Модульная архитектура бэкенда (Выполнено ✅):** `checkout-service.ts` успешно декомпозирован на независимые предметные сервисы в `lib/server/services/`.

## 4. API Ручки (Route Handlers)

### ✅ Сильные стороны:
1. **Стандартизация ответов:** API возвращает структурированный JSON `{ success: true, ... }` или `{ success: false, error: '...', details: ... }`.
2. **Корректные HTTP статус-коды:** `400` для Malformed JSON, `422` для ошибок валидации схем, `429` для Rate Limit, `201` для успешного создания ресурса.
3. **Безопасная обработка вебхуков Stripe:** `apps/landing/src/app/api/landing/webhooks/stripe/route.ts` получает `request.text()` (сырой body) и верифицирует `stripe-signature`.

### 🎯 Статус улучшений:
1. **Идемпотентность создания бронирований и сессий Stripe (Выполнено ✅):**
   - Клиент генерирует стабильный `idempotencyKey` на сессию чекаута.
   - Серверная функция `createReservation` проверяет наличие существующей брони с тем же ключом (`session_id`) и возвращает её без дублирования записей в базе данных.
   - Вызовы `stripe.checkout.sessions.create()` снабжены нативной опцией `{ idempotencyKey }`, исключая повторные списания и дублирование сессий в Stripe при нестабильном мобильном интернете.
2. **Rate Limiting с заголовком Retry-After (Выполнено ✅):**
   - Усилен `rate-limit.ts` с точным расчетом `retryAfter` и генерацией стандартных HTTP-заголовков `429 Too Many Requests` + `Retry-After`.
   - Защищены все критические ручки (`/reserve`, `/stripe-session`, `/check-fee`, `/contact`, `/magic-link`) без усложнения стека и без лишних расходов на платный Redis.

## 5. SEO и поисковая оптимизация

### ✅ Сильные стороны:
1. **Динамический Sitemap (`/sitemap.xml`):** `sitemap.ts` автоматически подтягивает активные курсы из базы данных и формирует актуальные ссылки с `priority` и `changeFrequency`.
2. **Семантическая микроразметка Schema.org (JSON-LD):**
   - В `layout.tsx` объявлена организация `EducationalOrganization` с полным адресом (Cittanova), гео-координатами, телефоном, соцсетями и диапазоном цен.
   - В каталоге и на странице курса рендерится `CourseSchema` с описанием и ценой.
3. **Мета-теги и соцсети:** На всех страницах настроены `canonical` URL, `openGraph` (с картинками 1200x630) и `twitter:card`.

### 🎯 Статус улучшений:
1. **Хлебные крошки (`BreadcrumbList` JSON-LD) (Выполнено ✅):** Создан компонент `BreadcrumbSchema.tsx` и интегрирован на страницы курсов `/corsi/[id]` и статей блога `/blog/[slug]`. Поисковики получают готовую иерархическую структуру `Home › Corsi / Blog › Название`.
2. **Кэширование генерации Sitemap (Выполнено ✅):** `sitemap.ts` обёрнут в `unstable_cache` с тегом `CACHE_TAGS.COURSES` и часовым TTL (`revalidate: 3600`), полностью устраняя лишнюю нагрузку на Supabase при краулинге ботами.

## 6. Безопасность и соответствие GDPR

### ✅ Сильные стороны:
1. **Строгий Content Security Policy (CSP) & Заголовки:** В `next.config.mjs` настроены `Strict-Transport-Security` (2 года + preload), `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`.
2. **Разделение ключей доступа:** Клиент оперирует только `anon`-ключом, `service_role` используется исключительно на сервере.
3. **Cookie Banner & Consent:** Присутствует баннер согласия на куки, интеграция с аналитикой уважает выбор пользователя.

### 🎯 Статус улучшений:
1. **CSP Hardening (Выполнено ✅):** Директива `'unsafe-eval'` полностью исключена из продакшен-сборки (`process.env.NODE_ENV !== 'production'`). Добавлена директива `upgrade-insecure-requests`, форсирующая безопасное соединение. Сохранён строгий доменный Whitelist (`Stripe`, `Google Analytics`, `GTM`, `Clarity`, `Supabase`) для идеальной совместимости с SSG/ISR кэшированием и маркетинговыми инструментами.
2. **Поддержка `prefers-reduced-motion` (Выполнено ✅):** В `ScrollAnimateProvider.tsx` настроен автоматический детектор `(prefers-reduced-motion: reduce)`, отключающий смещения и очищающий инлайн-стили.

### ✅ Сильные стороны:
